# Интеграция аккаунтов, dashboard и бесплатного поиска

Этот документ описывает локальный кандидат 15 ноября. До отдельного публикационного receipt действующим остаётся v36; наличие маршрута в коде не означает его доступность на домене.

- `/account`: обычный логин и пароль, закрепление прежнего guest ID, вход с другого устройства. Owner/admin/API права не выдаются. Почта и восстановление по письму не подключены, `email_verified:false`. Старый cookie закреплённого пространства без account session закрыт, после logout выдаётся отдельный guest при необходимости.
- `/dashboard`: отдельный admin username/password, cookie и CSRF, список реальных пространств/аккаунтов, доступные счётчики проверок и знаков, очереди, ошибки и история block/unblock. Пароли и чужие тексты не показываются. Покупки `null`, платежи `configured:false`: merchant не подключён.
- `/dashboard/pool`: staging, проверка бесплатного тарифа, активация/отключение и masked credentials. SerpApi/Tavily показывают наблюдённые provider counters с датой; Serper/Exa показывают неизвестный live-баланс отдельно от одобренного ограниченного гранта. Просто новый ключ не создаёт доказательство бесплатного бюджета или новый сброшенный счётчик.

Администратор использует отдельные приватные данные входа, вне Git и образа. Владельческий вход сайта и API bearer ими не заменяются. Панель защищена no-store/noindex, отдельным CSRF и ограничением попыток входа.

Все новые проверки используют закреплённые версии ключей. Exact replay возвращает старое задание, изменённое тело с прежним ID даёт409. Unknown quota/429/timeout не считаются исчерпанием; после неизвестного результата поисковый запрос не повторяется другим API. Неполный отчёт не означает100%уникальность. Планировщик по умолчанию остаётся v11; новый корпус пока не является доказательством роста коротких вставок.

Legacy cap180 сохраняется. Reviewed automatic cap900 — отдельная доверенная политика, с прежней историей calls. Статусы различают остатки; денежный расход разрешён только0. Бесплатные сервисы имеют конечные квоты и не гарантируют неограниченную работу24/7.

## Постоянное состояние и откат

Сохраняются текущий Volume, tenants, beta/search ledgers и owner denylist. Новые состояния: private/dashboard.sqlite3 + runtime/dashboard-initialized; private/user-access.sqlite3 + его.key + runtime/user-access-initialized; search-pool-vault целиком; runtime/pool-bootstrap.json; pool_job_pins в beta.sqlite3. Они входят в согласованный backup и локальную HTTP-проверку восстановления.

Сначала квалифицируется тот же source в aware-reader: существующие account claims/blocks/pins применяются, новые регистрации, блокировки и Pool POST отключены. Login/logout разрешены и могут писать сессии. Writer включает бизнес-изменения только после успешной квалификации. После первой новой регистрации/блокировки старый v36/v35 не является допустимым fallback: он не знает новых правил. Откат к aware-reader сохраняет текущее состояние и все счётчики, не восстанавливает старую базу поверх новой.

Bootstrap один раз использует реальные свежие read-only наблюдения, очищенные от ключей и лишних персональных полей. In-progress digest сохраняется до первого изменения vault; незавершённая попытка не перезапускается автоматически. Complete digest остаётся историческим receipt первоначального bootstrap. Для writer оператор получает новую свежую proof-порцию тех же одобренных ключей; она не перезаписывает complete marker и не повторяет bootstrap.

## Проверки и честные ограничения

Сохраняются отдельные owned review/test receipts. Combined HTTP/SQL, браузер, полные Python/Node, независимый source review и новый операторский пакет проверяются на точном SHA до публикации. Реальные значения, image ID, сохранность текущих данных и факт публикации фиксируются после выполнения, а не заранее. Платёжный checkout, восстановление пароля по email и бесконечные бесплатные квоты в этот релиз не входят.
