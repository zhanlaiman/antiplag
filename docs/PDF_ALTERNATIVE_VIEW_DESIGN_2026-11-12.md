# Дополнительный текстовый вариант PDF

Ограниченное добавление реализовано под выключенным по умолчанию флагом `ISTOK_PDF_ALTERNATIVE_ENGINE=pdfium`. Интерпретатор задаётся абсолютным `ISTOK_PDFIUM_PYTHON`; используется уже установленная библиотека, установки и модели не нужны. Политика `pdfium-spacing-primary-order-v1` зафиксирована до первой проверки зарезервированного RFC8259 в `docs/baselines/night-pdf-choice-2026-11-12.json`. Включение рабочего сайта требует проверки интеграции и этой первой проверки.

## Извлечение без изменения основного результата

Основной парсер остаётся `pypdf 7.0.1`. После успешного plain-извлечения можно получить ещё один текст из **тех же PDF-байтов** через уже доступный `pypdfium2 5.14.0`. Устанавливать пакеты или модели не требуется. PDFium используется только для извлечения текста; рендеринг, OCR, формы и JavaScript не нужны.

В начале `extract_pdf` фиксируется единый дедлайн `monotonic() + min(timeout, 5)`. Сначала запускается существующий worker. Дополнительный worker получает только оставшееся время; второй пятисекундный таймер не начинается. Если времени не осталось, зависимости нет или дополнительный worker отказал, возвращается прежний успешный plain-результат с записанной причиной отсутствия дополнительного варианта. Отказ plain, включая шифрование, превышение лимитов и отсутствие достаточного текстового слоя, сохраняет прежнюю типизированную ошибку. Дополнительный парсер не превращает такой отказ в успешное чтение.

Дополнительный worker запускается отдельным процессом через явно настроенный интерпретатор, с минимальным окружением без ключей, ограничениями CPU/RSS/вывода и родительским тайм-аутом. Сохраняются 1 MiB входа и 40 страниц. Общий объём сохранённых текстов двух вариантов ограничен существующими 200 000 знаками: если дополнительный текст не помещается, сохранить plain и причину пропуска. Native PDFium не наследует внутренние лимиты потоков pypdf; это требует отдельной проверки ресурсных отказов до включения. Проверенная существующая библиотека: Python-обёртка 5.14.0, native PDFium 156.0.8076.0; версии записываются в диагностике опытов.

## Одна загрузка, два независимых снимка текста

URL и счётчик прочитанных страниц остаются одними. На границе загрузчика дополнительный текст передаётся в `supplemental_texts`, с теми же SHA исходного PDF и числом страниц. В отчёте выбран плоский совместимый формат независимых снимков:

```json
{
  "sources": [
    {
      "id": "web-<hash-url>",
      "url": "https://example.org/source.pdf",
      "text": "Основной plain-текст"
    },
    {
      "id": "web-<hash-url>-pdfium-v1",
      "representation_of": "web-<hash-url>",
      "url": "https://example.org/source.pdf",
      "text": "Дополнительный извлечённый текст",
      "provenance": {
        "text_sha256": "<sha256>",
        "raw_pdf_sha256": "<sha256 исходных байтов>",
        "pdf_pages": 1,
        "parser_version": "5.14.0",
        "evidence_policy": "pdfium-spacing-primary-order-v1"
      }
    }
  ]
}
```

`representation_of` связывает снимки; он не означает новый прочитанный источник. Счётчики `web.sources_checked`, `stats.checked_source_count`, публичный `source_snapshots_count` считают только основные снимки; `source_count` считает разные физические URL с подсветкой. Такой формат сохраняет обычные `source_id`, `source_start/source_end`, показ выдержки, экспорт и хранение: координаты относятся к одному полному сохранённому тексту. Отсутствие дополнительного снимка оставляет прежний путь выполнения. Допускается не более одного дополнительного варианта и суммарно не более 200 000 знаков двух текстов.

Matcher проверяет каждый снимок независимо. Из дополнительного допускается только `exact`, без NUL, Unicode noncharacters и суррогатов в обеих выдержках; все непробельные знаки выдержки должны подряд в том же порядке присутствовать в основном снимке. Правило не меняет знаки и не склеивает части разных представлений. При равных диапазонах предпочтителен основной вариант; более полный диапазон может ссылаться на PDFium. Доля подсвеченных слов считается по объединению диапазонов проверяемого текста, пересечения не считаются дважды. Дополнительный `similar` не допускается. Избыточная основная fuzzy-область удаляется только когда её весь исходный диапазон уже покрыт подтверждённой exact-выдержкой.

## Координаты и проверка доказательства

У новой подсветки `source_id` указывает на отдельный полный снимок. `source_start/source_end` относятся строго к этому тексту. Поле `pdf_spacing_evidence` сохраняет ID основного снимка, диапазон подтверждения, SHA основного текста, SHA его выдержки и SHA последовательности непробельных знаков.

Оценщик проверяет сохранённую выдержку, её диапазон и `literal_equivalent`, затем заново рассчитывает подтверждение по основному снимку и требует точного равенства `pdf_spacing_evidence`. Отсутствие основного снимка, другой URL или подмена диапазона делают подсветку недостоверной. Подставлять основной текст вместо отсутствующего дополнительного нельзя.

Интерфейс и HTML-экспорт показывают сохранённый `source_excerpt`; отдельный экран для PDFium не требуется. Проверка через UI должна подтвердить выдержку и URL, сохранение после повторного открытия и единственный физический источник в счётчиках. SQLite сохраняет оба снимка целиком. Инструмент повторов обязан восстанавливать основной текст и дополнительный вариант при одном URL, не перезаписывая основной последним элементом списка.

## Зарезервированный материал и границы проверки

`scripts/reserve_pdf_holdout.py` сохраняет исходные байты через обёртку существующего `extract_pdf`, затем baseline worker JSON, нормализованный plain-текст, SHA, URL и время. Содержание не печатается, выдержки не выбираются. Попытки журналируются до сети и не повторяются автоматически.

- RFC8259 зарезервирован 12 ноября в 00:12:24 по Алматы: 22 750 байт, 16 страниц, 23 656 знаков plain. SHA PDF `36eae5d5812250c57e31cd87e591e6fd63fa2384ac4d8c53d7e0306807c75680`; SHA нормализованного plain `8530578cbc352c445ca5dd9ac92196e540c72778f78e75d31b2fa7beae9325c4`.
- Заданный URL PDF RFC2606 завершился `http_error`; байтов нет. Родитель открыл информационную страницу, поэтому этот материал исключён из закрытой проверки.
- Единственная отдельно разрешённая замена RFC3339 завершилась HTTP 404; байтов нет. Другие адреса не подбирались.

Таким образом, сейчас зарезервирован **один доступный PDF**, а не два. Всего выполнены три явно разрешённые прямые попытки; поисковых и модельных вызовов нет. Финальные 70 не открывались. Каталог `data/private/web-evaluation/pdf-unfamiliar-reserved-v1` остаётся закрытым до выбора политики вариантов; отказавшие URL не следует учитывать как успешные случаи извлечения.

Перед включением нужны: неизменность прежних подсветок на сохранённых случаях, проверка прироста D06/D20 и отрицательных пар без новых необоснованных выделений, затем одна первая проверка выбранного варианта на доступном зарезервированном PDF. Если понадобится два успешных новых PDF, второй источник ещё нужно получить отдельной разрешённой попыткой. Разбор обнаруженных там ошибок будет означать использование этих примеров для настройки.
