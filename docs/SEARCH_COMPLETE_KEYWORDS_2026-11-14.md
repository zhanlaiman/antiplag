# Полное поле ключевых слов для поиска источника

В сохранённом нулевом отчёте скопированной научной статьи исходный HTML читается обычным Fetcher и даёт 692/692 слова при условном локальном сравнении. Автоматический поиск не обнаружил исходную страницу. Дополнительный разрешённый опыт со строгим `exact_match` Tavily не исправил потерю: 0/692, 19 прочитанных страниц. Парный прежний запрос также не нашёл источник. Положительный контроль короткой вставки остался 9/9, отрицательный — ноль совпадений. Все исходы сохранены; строгий режим не включён в production.

Обнаружена отдельная потеря контекста: существующий запрос из поля «Ключевые слова» обрывается до названия культуры и способа защиты. Новый opt-in `hybrid-citation-v8-complete-keywords` заменяет только этот уже выбранный запрос полным содержимым явно подписанной строки. Поле содержит до 30 слов и 390 символов; должно добавляться минимум два слова. Поддерживаются `Ключевые слова:`, `Keywords:` и `Key words:` на отдельной строке. Сохраняются исходный порядок нормализованных слов и Unicode-границы. Поле используется как набор поисковых понятий без внешних кавычек. Текст, автор, заголовок и домен не угадываются и не подставляются извне.

Первый запрос, выбранные цитаты, число и порядок слотов сохраняются; заменяется максимум один слот. При меньшем allowance 1–5 действует прежний план. Поиск остаётся Tavily Basic с прежними параметрами и без строгого флага; matcher, пороги, правила чтения, квоты и нейросети не меняются. На 30 DEV и уже открытых 70 известных текстах планы полностью совпали с v7; это сохранение этих планов, а не независимая точность.

После 13 попыток прежнего строгого опыта остаётся семь из разрешённых 20. До нового вызова фиксируются код, вход и единственный изменённый запрос. Если он обнаружит доступный исходный текст, до шести оставшихся попыток допускаются на публичную проверку того же документа после тестов и публикации. Это диагностический повтор известного случая; source URL используется только при оценке найденных результатов. Если запрос не найдёт страницу, кандидат не считается исправлением этого пропуска. Исходные 0/692 и неудачный строгий опыт не заменяются.

Опубликованная версия и фактические результаты фиксируются в HANDOFF.md. Приватные тексты и ответы API не включаются в Git.
