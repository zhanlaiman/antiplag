Новые фрагменты не раскрываются автору алгоритма до фиксации кандидата.

Русский текст официальных метаданных сопоставлен с последовательностью нормализованных символов исходного PDF. Семейства сохраняются независимо от будущего исхода: эти ограничения должны оставаться частью оценки, отдельно от планирования и discovery.

Инструменты:

- `scripts/science_pilot.py verify` проверяет инвентарь, SHA, точность обеих выдержек,9слов, UTF8/токены, уникальность UUID и порядок.
- `conditional` сравнивает только с известными аннотациями, блокируя socket/HTTP/urllib и сохраняя отдельные первые отчёты.
- `scripts/science_pilot_run.py bind` сохраняет Git archive единственного exact candidateSHA и выдаёт одну долговременную allocation на этот freeze; другой output-каталог не получает вторую квоту.
- `run` требует совпадающие freeze/candidate/planSHA, ссылку на общий аудит и фактическое разрешение владельца. Оба CLI требуют явную стратегию `hybrid-citation-v13-empty-nine-suffix-six`, закреплённую в config/authorization/intent/result; отсутствующая/иная стратегия отклоняется до transport, native fallback report сохраняется как failure. Только после этого native adapter заново подтверждает Free$0/extra0 и достаточный остаток. Максимум6 primary slots на случай,18 физических всего; повтор unknown запрещён, готовый run возвращается без перезаписи. Запросы генерирует только закреплённый код кандидата, включая его штатный adaptive slot; ручных замен нет.

Отчёты с нулём прочитанных страниц сохраняют unknown/null. Строгие Gold URL, другие подтверждённые источники и стадии discovery/fetch/match учитываются отдельно. Нового полного baseline-прогона нет; отсутствие общего ответа при сравнении должно обозначаться `not_tested`.

## Repair после независимого FAIL инструментов

Независимый review `add3afe` нашёл два блокера: копия freeze под другим родителем получала вторую18-call allocation с тем же разрешением; SIGINT между сохранением неверного native report и `failure.json` позволял restart довериться наличию файлов. Исходный commit, FAIL и контрпримеры сохранены. Старые42 unit green этих границ не покрывали.

В repair allocation привязана к стабильному pilot_id = payloadSHA в пространстве одобренного плана; копии корпуса под тем же планом разделяют allocation. Authorization дополнительно обязана закреплять точные канонические corpus root, allocation anchor, output root и plan origin, поэтому копия плана не может повторно использовать исходное разрешение. Сам план хранится вне frozen data. При возобновлении все сохранённые отчёты заново проходят проверки input hash/text, точной стратегии, UUID/intent/query context, native closed-source validator, выдержек и source provenance SHA до создания клиента. Та же проверка действует при возврате полного run. Наличие или отсутствие failure marker не заменяет проверку самого отчёта.

Две регрессии сначала наблюдались RED. После исправления прошли18 pilot-тестов +28 прежних evaluator-тестов под запретом socket/HTTP/urllib; корректный межслучайный restart сохраняет6/18/12 и не повторяет готовый случай.
