# Диагностика внешних кавычек поискового запроса

**Свежая проверка завершена: снятие кавычек не помогло ни в одной из трёх пар.** По умолчанию остаются прежние запросы с кавычками. Новый вариант только удаляет первый и последний символ `"`; слова, пробелы внутри фразы, позиции в документе, порядок и число запросов сохраняются. Написание и границы D02 не исправляются.

Локальная неизменность выбора фраз доказана устройством преобразования: каждый элемент плана копируется, меняется только оболочка `query[1:-1]`, затем сверяются последовательности нормализованных слов и исходные границы. Поэтому для любого допустимого плана и любой разметки число фраз, целиком попавших во вставку, одинаково. Это не доказательство одинакового поведения поисковика. Прямо срезать `[1:-1]` при подсчёте уже снятых кавычек нельзя: такая старая вспомогательная функция обрежет буквы слов. Здесь сравниваются токены фразы.

Восемь авторских тестов проходят, включая 13 искусственных документов со вставками 10/20/40 слов в четырёх позициях и примером двух вставок. Для выбранных трёх DEV-входов отдельно сохранено: полный план **6 → 6** в каждом, слова/границы/порядок одинаковы; выбранные фразы во всех трёх случаях содержат **10 → 10** слов. Полные тексты, исходные страницы и эталонные URL для преобразования не используются.

До живой проверки заранее заданы пары: **D01 индекс 1, D02 индекс 1, D20 индекс 0**; индексы с нуля. По одному запросу с кавычками и без них на каждый документ, суммарно не больше шести Tavily Basic. Это диагностический выбор уже известных проблемных запросов, не новая стратегия выбора фраз. Отдельный однофразный опыт не оценивает качество всей шестизапросной стратегии и не даёт устойчивой оценки поведения поисковика по одному ответу.

Драйвер `scripts/run_query_format_pairs.py` сохранил частный manifest `dev-query-format-pair-v1/run.json` и локальную проверку `local-invariance.json`. Затем root разрешил ровно шесть Basic-вызовов после сверки SHA и свежей бесплатной квоты. Все шесть отчётов получены через обычную HTTP-очередь и сохранены в основном Store. Использованы UTF-8 JSON, стабильные идентификаторы и GET перед возможным POST; отправленный или неопределённый вызов не повторяется. Сохранены ответы поиска и полные допустимые результаты обычного Fetcher; метки и правильные URL не передавались backend.

| Выбранный фрагмент | С кавычками → без кавычек | Ожидаемый URL прочитан |
| --- | ---: | --- |
| D01, 10 скопированных слов | 0/10 → 0/10 | нет → нет |
| D02, 9 скопированных слов | 0/9 → 0/9 | нет → нет |
| D20, только первая вставка, 11 слов | 11/11 → 11/11 | да → да |

По каждой стороне: **1/3 полных выбранных фрагмента, 11/30 слов**, ожидаемый URL найден и прочитан в **1/3**. Непосредственно в поисковых ответах ожидаемых URL **0/3**: D20 найден через настоящую ссылку прочитанной страницы. Порядок пяти URL прямого ответа одинаков в каждой из трёх пар. Две D20-пары выдержек проверены буквально, в остальных четырёх отчётах подсветок нет. Ложных и неподтверждённых пар — 0/6 отчётов. Вторая вставка D20 не является выбранной целью этого одиночного запроса и не включена в знаменатель трёх диагностических фрагментов.

Это шесть отдельных однофразных заданий на трёх знакомых документах. Их нельзя подменять полным шестизапросным прогоном 30 случаев или складывать с ним как независимый выигрыш. Вывод отрицательный: в этих трёх единичных наблюдениях выгоды удаления кавычек нет; устойчивость поисковика и другие документы так не оценены. Новая стратегия не включалась.

Частные `comparison.json` и `accounting.json` сохраняют доказательства. Все **6/6** маркеров завершены и имеют явный расход по одному кредиту: **6 бесплатных Basic-кредитов**. После опыта месячный локальный журнал — **506**, из них 468 с начала исходных 30 и 400 в продолженной работе. Свежий снимок квоты после опыта: Researcher1000, paygo0; показатель API499 отстаёт от локального журнала. Расход **0 ₸**. Учёт воспроизводит `scripts/query_format_accounting.py`, различающий явный нулевой кредит и отсутствие сведений.

Переиспользованы ограниченный регистратор и восстановление GET из V2, а также частный writer/регистратор Fetcher из metadata-пилота. Для драйвера и V2 прошли **25 тестов**, ещё 11 авторских тестов проверяют отдельный учёт и его включение в общую сводку. Авторский HTTP-тест использует временный Store/журнал и поддельные ответы настоящего адаптера Tavily; повторное открытие всех шести заданий не добавляет вызовов. Перед START SHA кода должен совпасть с подготовкой. Если production изменится перед новым опытом, старый manifest сохраняется, а новая подготовка получает отдельную версию. Финальные 70 и закрытые RFC не открывались; моделей — 0.
