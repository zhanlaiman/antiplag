# Формат офлайн-сверки веб-отчётов

`plagiarism/web_evaluation.py` и `scripts/score_web_evaluation.py` читают сохранённые отчёты и ручную разметку. Они не запускают поиск, не скачивают страницы и не вызывают модели. Это инструмент сверки, а не готовый набор из 100 реальных случаев. Полный порядок сбора и бюджет описаны в [протоколе](EVALUATION_PROTOCOL.md).

## Какие файлы нужны

Manifest — JSON-объект с `schema_version: 1`, `cases` и SHA256 зафиксированной конфигурации. Каждый `report_path` указывает на полный приватный снимок, полученный через `Store`, с развёрнутыми `sources`, включая `source.text`. Файл может содержать сам отчёт или объект с полем `report`.

Публичный API не отдаёт полный `report.sources` с текстами источников. Скачанный публичный JSON нельзя автоматически считать пригодным для scorer. Нужны исходный `report.text`, `scope: "web_search"`, `sources`, `matches` и `web`. Подсветка сверяется с текстом документа, снимком источника, URL и границами. Неподтверждённые выдержки фиксируются как ошибки и не превращаются в успешные находки.

Относительные пути разрешаются от папки manifest. Полные снимки, исходные тексты и разметку хранить приватно, отдельно от публичного Git. Получение полного снимка не означает разрешение публиковать чужой текст или использовать его для обучения.

## Поля manifest и случая

| Поле | Значение |
| --- | --- |
| `frozen_config_sha256` | SHA256 байтов зафиксированного файла конфигурации, 64 символа `0–9a–f`. Для `test` обязателен; для рабочего baseline заполнять сразу. |
| `cases` | Непустой массив случаев. Наличие массива не доказывает реальность или качество разметки. |
| `id` | Уникальный идентификатор случая. |
| `document_id` | Идентификатор документа. Его текст, семейство и раздел должны быть согласованы во всех записях. |
| `family_id` | Общее семейство исходника, версий, перепечаток и переводов. Одно семейство не может попасть в `dev` и `test`; одинаковый gold URL или SHA эталонного источника также не может пересекать разделы. |
| `split` | `dev` или `test`. План — около 30 настройочных и 70 независимых случаев, разделённых целыми семействами до настройки. |
| `scenario` | `copy`, `short_insertion`, `multiple_sources`, `quote`, `paraphrase`, `translation`, `independent` или `template`. |
| `synthetic` | Булево происхождение примера. `false` допустимо для настоящего реального случая, а не для переименованной генерации. |
| `reviewed` | Булев факт ручной проверки разметки. Успешная валидация JSON не делает его `true`. |
| `text_sha256` | SHA256 UTF-8 байтов точного `report.text`, включая пробелы и переносы. |
| `report_path` | Путь к сохранённому полному отчёту. |
| `expected_evidence` | Массив ожидаемых текстовых связей с источниками. Для нескольких источников нужны отдельные записи. |

Одинаковый текст нельзя объявить разными независимыми документами. Пересечения семейств, документов и повторная разметка проверяются для всего manifest до выбора раздела. Непросмотренные случаи исключаются из итоговых метрик, синтетические и реальные показываются отдельно. Ноль просмотренных реальных случаев означает, что качество на реальных данных ещё не измерено.

## Ожидаемое свидетельство

| Поле evidence | Значение |
| --- | --- |
| `source_urls` | Непустой список gold URL и заранее разрешённых эквивалентов. Зеркала/редиректы перечисляются явно. Query-параметры значимы и не отбрасываются. Кириллица в пути приводится к URI-представлению; закодированный слеш не превращается в обычный. |
| `target_span` | Ожидаемый участок проверяемого документа `[start, end)`. |
| `source_span` | Участок эталонного текста источника `[start, end)`. |
| `needs_lexical_highlight` | Нужна ли дословная подсветка для данного свидетельства. `false` подходит для пересказа/перевода без ожидаемого дословного совпадения. |

Границы считаются по Unicode-символам Python, как `Array.from(text)` в интерфейсе, а не по UTF-8 байтам или UTF-16 индексам. `start` включён, `end` исключён. Сам `source_span` проверяется по структуре; непрочитанный источник не должен ломать загрузку случая.

Для независимой проверки эталонного участка можно добавить вместе `source_snapshot_path` и `source_text_sha256`. Это UTF-8 файл и SHA256 его байтов. Необязательный `source_quote` сверяется с выбранным участком этого снимка. Без эталонного снимка нельзя выдавать структурно допустимые числа за подтверждённую привязку к нужной редакции страницы.

Gold URL используется **только при офлайн-сверке**. В тело главной кнопки идут `request_id`, `text`, `internet_consent`; ожидаемый URL, метка и gold-границы туда не добавляются. Ссылка, уже присутствующая в исходной статье, обрабатывается по правилам скрытого поиска из протокола.

Прочитанный нужный источник при `needs_lexical_highlight: false` означает найденную доступную страницу. Это не доказательство, что приложение обнаружило пересказ или перевод. Результат поиска, дословное сопоставление и смысловая/редакторская оценка остаются разными измерениями.

Корректную цитату и реально совпадающее общее определение размечать как evidence. Оформление ссылки, допустимость шаблона и вывод о нарушении хранить отдельно в редакторской разметке. Они не исчезают из совпадений из-за своей легитимности.

`expected_evidence: []` означает только вручную проверенное отсутствие ожидаемой лексической связи в этом случае. Для просмотренной пустой разметки предусмотрены сценарии `independent` и `template`. Это не метка «плагиата нет». Если у шаблона есть настоящее ожидаемое совпадение, нужен evidence, а не пустой массив. Опубликованная статья может найти саму себя; для независимого неопубликованного отрицательного примера требуется согласие автора на отправку поисковых фрагментов провайдеру.

## Шаблон, не готовый случай

Все SHA, URL, пути, идентификаторы и границы ниже — заглушки. JSON синтаксически корректен, но намеренно не является валидным реальным набором. Не заменять ручную проверку переключением `reviewed`.

```json
{
  "schema_version": 1,
  "frozen_config_sha256": "REPLACE_WITH_BASELINE_FILE_SHA256",
  "cases": [
    {
      "id": "replace-case-id",
      "document_id": "replace-document-id",
      "family_id": "replace-family-id",
      "split": "dev",
      "scenario": "copy",
      "synthetic": false,
      "reviewed": false,
      "text_sha256": "REPLACE_WITH_EXACT_REPORT_TEXT_SHA256",
      "report_path": "reports/replace-full-private-snapshot.json",
      "expected_evidence": [
        {
          "source_urls": ["https://example.invalid/replace-source"],
          "target_span": [0, 1],
          "source_span": [0, 1],
          "needs_lexical_highlight": true
        }
      ]
    }
  ]
}
```

## Команды

Сначала получить настоящий хеш файла baseline и записать его в manifest. CLI сравнивает переданное значение с manifest; сам по себе этот флаг не проверяет Git и не читает baseline вместо вас.

```sh
shasum -a 256 docs/baselines/web-v1-2026-11-11.json
python3 scripts/score_web_evaluation.py data/private/web-evaluation/manifest.json --split dev --output data/private/web-evaluation/dev-score.json
```

Только после фиксации параметров и выбора победителя на `dev` открыть независимый раздел. В следующей команде заменить `ACTUAL_BASELINE_SHA256` настоящими 64 символами из первой команды. Пути примерные, сами данные и родительская папка для `--output` должны существовать.

```sh
python3 scripts/score_web_evaluation.py data/private/web-evaluation/manifest.json --split test --allow-test --frozen-config-sha256 ACTUAL_BASELINE_SHA256 --output data/private/web-evaluation/test-score.json
```

По умолчанию используется `dev`. `test`, а также `all`, включающий тестовые случаи, требуют явного разрешения и совпадения SHA. `--format json` выводит полный результат; `--format table` — компактную таблицу. Имена агрегатов могут меняться вместе с валидаторами, поэтому не строить вывод о качестве по одному названию поля summary.

Сохранённое время и число запросов суммируются по уникальным отчётам, а не по числу размеченных участков одного документа. Неизвестные исходы остаются в общем знаменателе конечного результата; отсутствие аудита URL выводится отдельно. Неожиданные exact-подсветки означают расхождение с ручной разметкой, а не автоматический вывод о плагиате.

Находка в частичном отчёте остаётся находкой. Ноль подсветок при неполном охвате — неопределённый исход, а не доказательство уникальности. Git фиксирует код и параметры, но не живой индекс и страницы; сохранять время получения, SHA текстов, URL, ошибки и попытки бюджета рядом с отчётами.
