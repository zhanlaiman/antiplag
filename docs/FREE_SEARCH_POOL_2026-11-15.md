# Автоматический бесплатный поиск: серверный контракт

Серверная реализация подготовлена 15 ноября. Это **не сообщение о публикации**: текущий проверенный production остаётся v36. Включение требует проверенного объединённого релиза, актуального согласия в форме, новых секретов и подтверждения бесплатных лимитов. Регистрация, административный dashboard и управление ключами готовятся отдельными чатами.

Новый запрос в онлайн-бету содержит `internet_consent: true`, `search_provider: "auto"`, `provider_consent_version: "search-pool-v1"`. В этой версии фиксирован порядок: SerpApi/Яндекс → Serper/Google → Tavily → Exa. Поле `provider_consent` в новом теле отсутствует. `/api/status` возвращает `web.automatic_search` с `enabled`, `consent_version`, упорядоченным `providers`; чтение статуса не вызывает поисковые API. Старые сохранённые тела не меняются и используют прежний сервис. Изменённое тело с прежним ID получает 409. Beta `/api/v1/checks` передаёт этот же контракт; отдельный generic/SaaS server отклоняет новый режим до отправки поиска.

Перед первым поиском выбирается один провайдер на всё задание. Переход к следующему разрешён лишь при подтверждённой нехватке бесплатной квоты на весь план. Пустая выдача, неверный ключ, неизвестный тариф, таймаут, HTTP429 или повреждённый ответ не означают исчерпание и не запускают переход. После начала поиска неизвестный результат останавливает план; уже отправленный запрос не повторяется другим сервисом. Частичный отчёт не становится доказательством уникальности.

Все провайдеры в автоматическом режиме используют текущий планировщик v11. Отчёт сохраняет фактически выбранный сервис, планировщик и список пропущенных исчерпанных провайдеров. Специальные адаптивные правила Яндекса остаются только у Яндекса. Массовое включение экспериментального v13 этим изменением не выполняется.

Существующий общий месячный лимит сайта **180** сохраняется вместе со всеми строками `calls`. При 177 использованных запросах план из шести не начинается ни у одного провайдера. Для каждого отправляемого запроса одна SQLite-транзакция записывает прежнюю строку `calls` и метаданные `pool_calls`. Неизвестные исходы остаются израсходованными. `persist()` завершается до отправки HTTP. Смена ключа не очищает историю. Счётчик отдельного одобренного гранта не обнуляется в начале месяца; конфликтующая политика того же гранта отклоняется под SQL-блокировкой.

SerpApi проверяется через Account API: только Active Free Plan, 250, цена 0, extra 0 и согласованные счётчики. Для Tavily читается реальный `/usage` envelope `account`, принимается только Researcher1000/paygo0 и защитный порог900. Serper/Exa не имеют подтверждённого доступного публичного endpoint остатка с имеющимися search-ключами: нельзя показывать выдуманный live-баланс. Для них нужен отдельный серверный ограниченный грант с provider/account/grant binding, fingerprint ключа, сроком действия, неизменяемым cap, proof SHA256, `cash_spend_limit_usd: 0` и фиксированной стоимостью запроса. В браузере нельзя создавать одобрение гранта. При отсутствии подтверждения поиск закрыт.

Exa запрашивается только как Lite, не более пяти результатов, без извлечения contents и AI-синтеза; присутствующее значение `costDollars.total` проверяется в диапазоне 0…0.004 USD бесплатных кредитов. Serper ограничен одним поисковым запросом и пятью URL; служебные Google goto/url считаются неподтверждёнными адресами. Поисковые snippets не используются как доказательства совпадения: совпадения по-прежнему вычисляются по загруженным доступным источникам.

Секреты хранятся вне Git либо в серверном secret environment. Ключи не выдаются через статус, отчёты или ошибки. Оператор публикации должен отдельно заменить прежний production SerpApi-ключ: локальная ротация файла не меняет уже созданный Modal secret. Общие квоты, пользовательские данные, текущий Volume и denylist выхода владельца должны сохраниться.

Проверки: `python3 -m unittest tests.test_search_pool tests.test_search_pool_api tests.test_search_serper tests.test_search_exa -q`; общие существующие проверки `python3 -m unittest discover -s tests -q` и `node --test tests/*.test.cjs tests/*.test.mjs`. Числа, точный SHA, независимый аудит и публикационный receipt фиксируются после их фактического завершения. Новые научные материалы заморожены отдельным оценочным чатом; подготовка корпуса не равна проверке качества поиска.

Официальные основания: [Serper и стартовые кредиты](https://serper.dev/), [Tavily credits](https://docs.tavily.com/documentation/api-credits), [Tavily usage](https://docs.tavily.com/documentation/api-reference/endpoint/usage), [Exa search](https://exa.ai/docs/reference/search), [Exa pricing](https://exa.ai/docs/admin/pricing). Для Serper точная live-схема POST дополнительно требует наблюдения официального Playground или ограниченной проверки; синтетические тесты не доказывают доступность реального сервиса. Бесплатные квоты конечны: четыре сервиса не дают гарантии бесконечных проверок 24/7.
