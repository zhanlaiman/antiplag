# Первая проверка полностью новых источников V2

Подготовлен драйвер `scripts/run_unfamiliar_query_v2.py`. Он ещё не открывал RFC-тексты и не запускал живые запросы. Неизменный план, записанный до раскрытия, содержит два авторских основания по 35 слов, два независимых контроля и шесть искусственных вставок: по 10/20/40 слов из каждого из двух заранее фиксированных источников. Позиции источника и вставки заданы заранее, содержание не использовалось для выбора. CSS исключён из этой проверки после настройки HTML-парсера; RFC9309 и RFC1149 остаются закрытыми.

Исходный план с пределом 36 сохранён без изменений. Отдельная поправка, также записанная до раскрытия, исправляет арифметический потолок на **48 = 8 × 6**. Документы, позиции и тексты оснований не менялись. Перед каждым новым POST требуется свежая бесплатная квота: Researcher1000, paygo0, `max(показание API, локальный журнал) + оставшиеся планы ≤ 900`.

До `--reveal` root должен записать `docs/baselines/query-first-use-v2-choice-2026-11-12.json` с полями:

```json
{
  "frozen": true,
  "frozen_at": "UTC timestamp",
  "git_head": "tested 40-character commit",
  "plan_sha256": "b6e6a86cbb4c9e166b624115070aaa080f87b527acb9e9e93ed889bd17141bd4",
  "amendment_sha256": "ead96eae5382de36740761431c131a21dbff46ec2ef10a58f42e524c80ed03c4",
  "query_strategy": "selected constant value",
  "url_strategy": "selected constant value",
  "named_references": true,
  "zero_fallback": true,
  "pdf_alternative_engine": "pdfium",
  "matcher_version": "selected constant value",
  "html_extraction_version": "html-parser-v2-implied-ends"
}
```

Сам драйвер и импортируемые вспомогательные скрипты должны уже входить в проверенный коммит. `named_references` и **обязательное** `zero_fallback` выбираются явно как `true` или `false`; допускается `null` вместо PDFium. Старые choice без `zero_fallback`, числа 0/1 и строки намеренно не принимаются. Драйвер сверяет SHA кода и состояние Git **до** чтения источников; результат первого раскрытия, планы и собственный manifest фиксируются. Прерывание раскрытия не разрешает выбор других выдержек или повторное создание эксперимента.

`--reveal --expected-git-head COMMIT` выполняет только локальное построение. `--live --expected-git-head COMMIT` читает уже созданные входы и отправляет их через обычную HTTP-очередь в основной Store. Для каждого случая сначала выполняется GET по стабильному идентификатору; уже отправленный либо неопределённый POST не повторяется. Вызовы провайдера сверяются с точными сохранёнными фразами, ограничены шестью на документ и 48 суммарно. До отправки сохраняются идентичность и отметка попытки; сохраняются полные ответы поиска, полные результаты Fetcher и ссылки, в том числе причины отказа.

Замороженное `choice.zero_fallback` передаётся production как `use_zero_fallback`; отчёт обязан сохранить тот же булев флаг `web.zero_fallback_enabled`. Допустимый физический потолок — 24 попытки URL при `true` и 12 при `false`. Это потолок, а не требование дополнительных загрузок для положительного первого прохода. Ни локальное построение, ни подсчёт не выбирают значение по будущим результатам RFC.

`--score-only` использует только собственные сохранённые manifest/run/отчёты, не открывает резервирование, не строит планы и не обращается к сети. Он повторно сверяет флаг ZERO и его потолок, как остальные параметры выбранного варианта. Отдельно считает попадание целой фразы во вставку, обнаружение/чтение ожидаемого URL, подсветку от ожидаемого и от любого источника. Оба контроля и любые неожиданные пары выводятся с обеими выдержками как `needs_pair_review`; наличие пары само по себе не считается ложным совпадением. Первая проверка не используется для дальнейшей настройки.

20 авторских тестов проверяют закрытый режим по умолчанию, барьер заморозки, фиксированное построение без замены неудачного отрезка, GET-первым и отказ повторного POST, запись попытки до вызова, оба потолка запросов, проверку точной фразы и отсутствие сети/планировщика/чтения резервов при повторном подсчёте. Дополнительно проверены обязательность булева ZERO, точное имя production-параметра, совпадение флага отчёта и границы 12/24. Все 20 проходят. Счётчик расхода сверяет заявленные в отчётах вызовы с маркерами каждого случая; при пробелах общий расход остаётся неизвестным, а не нулевым. Финальные 70 не читались.
