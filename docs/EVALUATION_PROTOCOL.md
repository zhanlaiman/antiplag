# Проверка на реальных редакторских материалах

Цель — выяснить, какие источники и фрагменты находит Исток, какие ошибки добавляет или снимает Qwen и сколько времени занимает проверка у редактора. Текущие синтетические примеры уже использовались при настройке. Их результаты служат диагностикой разработки. Для проверки на новых материалах нужен отдельный набор.

## Набор примерно из 100 случаев

Один случай связывает проверяемую статью, конкретный участок для сверки и сохранённый источник либо тематически похожие независимые публикации. Несколько участков одной статьи получают общий `document_id`, чтобы при подсчёте времени и ложных подсветок статья учитывалась один раз.

Ориентировочное распределение

| Сценарий | Случаев | Что включить |
| --- | ---: | --- |
| Дословные копии | 20 | Копирование абзацев, вставки в авторский текст, небольшие изменения пунктуации. |
| Глубокие пересказы | 20 | Сохранённые факты, примеры и ход аргумента при существенно изменённой формулировке. |
| RU–EN | 15 | Реальные переводные или близкие по содержанию русско-английские фрагменты, по возможности в обоих направлениях. |
| Оформленные цитаты | 15 | Действительная цитата с указанием источника, включая цитаты среди авторского текста. |
| Независимые описания одного события | 15 | Совпадающие тема, имена и числа при самостоятельных деталях и формулировках. |
| Общие определения и шаблоны | 15 | Учебные определения, типовые вводные и устойчивые формулировки, в том числе из биологии. |

Числа можно немного менять по доступным материалам, сохраняя отчёт по каждому сценарию. Использовать опубликованные или предоставленные редактором реальные тексты. Сгенерированные специально для испытания пересказы хранить в отдельной синтетической части.

Экономическая и биологическая подборки могут быть фоном библиотеки. Их наличие само по себе не даёт разметки заимствований. Для пересказов и переводов сходство размечается по содержанию пары. Направление копирования без дополнительных сведений остаётся неизвестным.

## Разделение до настройки

1. Присвоить каждой семье исходных публикаций `family_id`. В одну семью включить перепечатки, версии, связанные пересказы и переводы. Тексты об одном событии и общие шаблоны группировать вместе, если они могли бы раскрыть проверяемый пример при настройке.
2. Разделить семьи примерно на 30 случаев для настройки и 70 для независимой проверки. Сохранить представительство всех сценариев и список отложенных семей. Целая семья относится к одному разделу.
3. На части для настройки выбрать инструкции, пороги, размеры фрагментов и правила подсчёта. После этого зафиксировать независимую часть и версии кода, моделей, библиотеки и разметки.
4. Независимую часть открыть для оценки после фиксации конфигурации. Если по её ошибкам меняются инструкции или пороги, отметить её использование для настройки и собрать новый независимый набор для следующего вывода о качестве.

## Одна таблица разметки

Для каждого случая сохранить идентификаторы статьи и семьи, раздел, сценарий, исходные тексты, ссылки и версии публикаций. Для воспроизводимости сохранить файлы текстов и их SHA256. Указать точные ожидаемые выдержки и границы в проверяемом тексте и источнике. Для независимо написанных текстов сохранить тематические альтернативы, с которыми легко получить ложное срабатывание.

Редактор заполняет три отдельных поля

- **Наблюдаемое сходство** — дословное, возможный пересказ/перевод, общая тема или различное содержание. Для дословного совпадения нужны реально одинаковые слова. Для возможного пересказа отметить общие содержательные детали. Сомнение в разметке сохраняется отдельно.
- **Оформление источника** — корректно оформлено, отсутствует, требует проверки или не применимо. Кратко указать основание, например наличие точной цитаты и действительной ссылки.
- **Редакторский вывод** — требуется правка, допустимо с учётом контекста или не оценивалось. Вывод о нарушении требует отдельного разбора контекста и правил публикации.

Корректная цитата остаётся дословным совпадением. Независимые тексты могут иметь одинаковое определение или шаблон. Такое совпадение сохраняется в разметке сходства, его редакторская значимость оценивается отдельно.

До запуска моделей завершить разметку и отметить неоднозначные случаи. При одном редакторе полезно повторно проверить сомнительные пары в другой день. По ним показывать отдельное количество, сохраняя исходную разметку для воспроизводимости.

## Измерение поиска скрытого источника

Для положительного случая поместить правильную публикацию среди остальных материалов библиотеки. Передавать поиску текст статьи и общую библиотеку. Название правильного источника, его идентификатор и ожидаемую выдержку использовать только при подсчёте результата.

Сравнить BM25 и гибридный поиск на одной библиотеке и одинаковых окнах текста. Сохранить первые пять кандидатов каждого метода до вызова Qwen. В длинной статье top-5 относится к одному окну запроса. Для размеченного участка заранее выбрать окно с наибольшим пересечением с ним, при равенстве — более раннее. Поиск по всем окнам статьи и этот подсчёт должны быть одинаковыми для обоих методов.

- **Source hit@5** — доля размеченных положительных участков, у которых правильный источник входит в первую пятёрку. До запуска отметить допустимые эквивалентные перепечатки из той же семьи.
- **Span hit@5** — доля этих участков, у которых кандидат из правильного источника покрывает не менее половины ожидаемой исходной выдержки. Порог фиксируется до независимого прогона. Найденную публикацию с неверным абзацем учитывать отдельно.
- **Пропуски** — перечень не найденных источников и участков с разбивкой по сценарию. Сбой поиска сохранять отдельной причиной пропуска.

Для независимых текстов и общих определений попадание тематического кандидата в выдачу само по себе не считается ошибкой. Ошибка возникает при неверном сопоставлении фрагмента или необоснованной интерпретации сходства.

## Те же пары с Qwen и без неё

Зафиксировать список найденных пар. Для сравнения добавить одни и те же пропущенные правильные пары и трудные отрицательные пары в отдельную диагностическую часть. Пометить происхождение каждой пары. Добавленные вручную пары помогают оценить Qwen при известном источнике и не улучшают метрики поиска.

Для каждой пары сохранить две версии представления

- Исходные тексты и лексическая подсветка без Qwen.
- Те же тексты и подсветка с вердиктом Qwen, выбранными выдержками и состоянием неопределённости либо ошибкой.

Сравнивать одинаковые пары и сохранять полный ответ, время и версию модели. Проверять, относится ли выбранная выдержка к размеченному месту в обоих текстах. Наличие точной выдержки подтверждает её происхождение, смысловой вывод редактор оценивает отдельно.

Одному редактору удобно проверять по 10–15 случаев за сеанс. Версии A/B перемешать, скрыть название метода до сохранения решения и распределить повторное рассмотрение по разным сеансам. Если редактор узнаёт вариант по тексту или пояснению, это ограничение отметить в отчёте. Сначала сохранить свою оценку, затем открыть эталонную разметку.

## Что посчитать

| Показатель | Правило |
| --- | --- |
| Пропущенные случаи после проверки пар | Нужный фрагмент найден поиском, но отвергнут или остался неопределённым. Показывать отдельно от пропусков поиска. |
| Ложные подсветки на статью | Число неверно сопоставленных участков или неверных утверждений о сходстве на один `document_id`. Дубли одного участка объединять. Показывать среднее и число статей хотя бы с одной ошибкой. |
| Ошибочные редакторские тревоги | Корректная цитата, общее определение или допустимый шаблон ошибочно представлены как требующие исправления либо как нарушение. Считать отдельно от факта лексического совпадения. |
| Доля неопределённых | Число ответов, оставленных для проверки редактором, относительно всех проверяемых пар. Технические ошибки показывать рядом отдельным числом. |
| Минуты редактора | Время чтения отчёта, сверки источников и сохранения решения на статью. Ожидание модели записывать отдельно. Сравнить медиану времени A/B и количество решений, которые потребовали пересмотра. |

Показывать числитель и знаменатель, например 11 из 15, и результаты по каждому сценарию. Неопределённые ответы и ошибки сохранять в итоговой таблице. Для полноты поиска и итоговых пропусков они не превращаются в успешные отрицательные ответы.

Итог для выбора Qwen включает изменение пропусков, ложных подсветок, количества неопределённых и времени редактора на одинаковых парах. Отдельно привести полный путь от скрытого источника до решения редактора, включая пропуски поиска.

## Минимальный результат этапа

Сохранить таблицу разметки, список независимых семей, снимок корпуса, конфигурацию, найденные кандидаты, ответы модели и краткий отчёт с перечисленными метриками. Вывод ограничить проверенными жанрами, языками и библиотекой. Отдельно перечислить оставшиеся спорные случаи и примеры, которые войдут в следующую часть для настройки.

Текущие загрузчики диагностических наборов рассчитаны на синтетическую схему. Реальные случаи хранить отдельно с `synthetic=false`. До адаптации загрузчика этот протокол выполним через интерфейс, сохранённые отчёты и одну таблицу редактора. Реальный набор не следует обозначать синтетическим ради запуска существующего скрипта.
