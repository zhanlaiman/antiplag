## Бюджет, ошибки и повтор

Общий лимит 180 основных поисковых запросов в месяц не увеличен и не сброшен. До 6 интернет-проверок на гостя в сутки UTC, обновление в 05:00 Алматы. API использует тот же бюджет. Перед поиском подтверждаются бесплатная квота Tavily и paygo=0; при неопределённости запрос не отправляется. У `/usage` собственный предел 10 обращений за 10 минут: не запускайте быструю цепочку проверок. [Условия Tavily](https://docs.tavily.com/documentation/rate-limits).

HTTP 429 сохраняет Retry-After (при некорректном значении 600 сек) в SQLite; пауза переживает перезапуск. Тайм-ауты допускают до трёх read-only запросов квоты. Поисковые POST автоматически не повторяются. Дневная попытка возвращается только при доказанном отсутствии поиска до запуска или отказе очереди до резервирования. Идентификатор и отпечаток текста сохраняются. Неизвестный исход остаётся учтённым.

При потере ответа сначала GET `/api/jobs/{request_id}`. Для исправления внешней причины после известного нулевого расхода пользователь создаёт новую проверку; старый ID возвращает прежний исход. Пакет документов записывает ID до POST и после перезагрузки возобновляет только GET, а не оставшиеся отправки.

Modal: проверяйте фактические кредиты, Total spend и Spend limit $0 перед deploy. Включённые кредиты конечны. Не добавляйте постоянные веса моделей в Volume; Volume storage не равен бесплатному 1TiB сетевого egress. Денежные списания при проверках релиза были $0. Бюджет владельца 0 ₸; его самостоятельная покупка домена — отдельная операция.

## Проверка незавершённых задач

До пересоздания сервера считайте долговременные `model-request`, у которых ещё нет терминального `model-job`, а также нетерминальные исходы. Одна проверка по status в model-job недостаточна: запись итогового задания появляется после выполнения. Финальный production guard дал 0 таких резервирований в 13 базах пространств.

Проверить скачанную копию без сети, изменений данных, поиска и моделей:

```sh
python3 -m scripts.check_beta_backup .runtime/release-20261113/production-final-20261114
```

Валидатор проверяет пути, SHA/размер, SQLite quick_check, hash-only owner конфигурацию и нерешённые задания. Он выводит только числа; код завершения 3 означает незавершённые/неразрешённые резервирования. Дождитесь исхода существующего задания или восстановите его через обычный GET его владельца. Не отправляйте новый POST вместо неизвестного исхода и не обнуляйте журнал. Приватные preflight-скрипты в рабочей копии используют эту же SQL-проверку. Старые скрипты с одним фильтром model-job не являются достаточным разрешением на перезапуск.

## Откат кода

Последний проверенный CPU-источник сохранён в `seo-staged.json`; 68 хешей проверяются скриптом. Откат оставляет тот же поиск v6, SEO и панель данных. Защитный вариант отката выключает дополнительный Qwen; его сохранённые результаты и счётчики остаются. После отдельной проверки бесплатного бюджета и отсутствия активных заданий:

```sh
python3 .runtime/release-20261113/rollback-final.py
MODAL_CONFIG_PATH=.runtime/modal-config.toml .runtime/modal-venv/bin/python .runtime/release-20261113/rollback-final.py --deploy
```

Dry-run ничего не меняет. Deploy использует recreate прежнего App, текущий Volume и прежний хеш владельца; нейрокорректор отключается. Базы, cookies и квоты не откатываются. Не выбирайте старый rollback.py/rollback-features.py без оценки: ранний код снова создавал гостевые базы при опросе статуса и не знал всех новых ограничений.

После перезапуска GET своего отчёта должен совпасть с сохранённым JSON; проверяйте новый браузер, обычный GET, личный и общий остатки. HEAD пока возвращает 501, это не проверка доступности GET. Не повторяйте deploy вслепую при неизвестном исходе: сначала квитанция `.runtime/web-deploy/deployment.json`, состояние App и версия файлов.
