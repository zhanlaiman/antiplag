# Исток

Локальный инструмент для редактора, который сверяет статью со своей библиотекой, рассматривает найденные фрагменты и сохраняет решения по находкам. Рабочее название проекта — «Исток».

## Запуск

Нужен Python 3.11 или новее. У приложения нет сторонних Python-зависимостей. Ollama нужна для Qwen и поиска по смыслу, Node.js — для проверок разработки.

Откройте `Запустить Исток.command` или выполните в папке проекта

```sh
python3 scripts/start.py
```

Приложение доступно на <http://127.0.0.1:8766>. Главная страница показывает пример сравнения и ведёт в редактор. Прямая ссылка на редактор — <http://127.0.0.1:8766/#check>. Процесс работает до закрытия терминала или Ctrl+C.

Источники, отчёты, снимки публикаций, ответы Qwen и сохранённые решения находятся в `data/istok.sqlite3`. Черновик текста, выбранная модель, несохранённые комментарии и идентификаторы активных заданий сохраняются в браузере. Для восстановления используйте тот же браузер и адрес с портом 8766.

## Первая проверка

1. Нажмите «Посмотреть пример» на главной. Проверка учебной статьи использует два специально написанных источника и сохраняет отчёт в истории. Ваш текущий черновик остаётся в редакторе.
2. Откройте «Источники». Можно установить готовую подборку по экономике или добавить свои материалы через вставку текста и файлы TXT/MD.
3. В редакторе вставьте статью и нажмите «Проверить текст». Подсветка ведёт к соответствующему отрывку источника.
4. Подтвердите или отклоните лексическую находку, при необходимости сохраните комментарий.
5. Запустите отдельный поиск пересказов. Рассмотрите кандидатов по словам и смыслу, сравните их с Qwen по одному или массово.
6. Просмотрите предложенную цитату или правку перед применением и повторно проверьте изменённый текст.

Проверка охватывает добавленную библиотеку. Ссылка, указанная при добавлении источника, сохраняется для отчёта. Содержимое произвольной веб-страницы автоматически не скачивается. Поиск по открытому интернету ещё не подключён.

Доля лексических совпадений рассчитывается по объединению найденных символьных интервалов относительно всей длины текста. Пробелы внутри интервалов учитываются, пересечения считаются один раз. Решения редактора и кандидаты поиска по смыслу сохраняются отдельно от этого процента. Оформленная цитата продолжает совпадать с источником.

## Библиотека и открытая подборка

В текущей рабочей базе находятся 14 реальных русскоязычных статей об экономике из Википедии и два учебных источника. Подборка хранится в `data/source-packs/economics-ru-v1.json` и устанавливается через экран библиотеки. Повторная установка сохраняет уже добавленные материалы. Пользовательские источники остаются в библиотеке.

У публикаций сохранены авторская атрибуция, лицензия CC BY-SA 4.0, ссылка на историю авторства, сообщённая API редакция, время получения и SHA256 извлечённого текста. В интерфейсе доступны сведения об авторстве и лицензии. Полный полученный обычный текст сохранён без обрезания. MediaWiki одновременно сообщает последнюю редакцию, тождество извлечения именно этой редакции отдельно не подтверждалось. Эта граница отражена в `provenance.revision_binding`.

Подборка служит начальной библиотекой для редакторских проб. Независимая разметка реальных заимствований по этим статьям ещё предстоит. Числа диагностических прогонов ниже получены на специально написанных синтетических примерах.

Отчёты сохраняют снимки источников и остаются читаемыми после удаления материала из библиотеки. Одинаковые снимки дедуплицируются по SHA256. Поддерживается чтение старых отчётов с вложенными текстами.

## Импорт и черновики

Текст статьи и отдельный источник могут содержать до 200 000 Unicode-символов. Ограничение проверяется явно при вводе, импорте и на сервере. Длинный вставленный текст сохраняется с видимым сообщением об ограничении.

Поддерживаются UTF-8 и UTF-16LE/BE с BOM. При некорректном UTF-8 без BOM пробуется Windows-1251, предположительная кодировка отмечается в интерфейсе. Двоичные данные, NUL и неподдерживаемые кодировки отклоняются до замены текста. Отложенное чтение файла сохраняет более новую правку пользователя.

Изменение текста помечает предыдущий отчёт устаревшим. История предлагает явное восстановление текста отчёта, сохраняя текущий черновик при открытии. Комментарии к находкам и учебным парам сохраняют новые изменения, сделанные во время ожидания ответа сервера.

## Локальные модели

Ollama обслуживает модели через <http://127.0.0.1:11434>. Стартовая модель сравнения — `qwen3:4b`. В интерфейсе можно выбрать другую установленную текстовую модель.

В текущем рабочем экземпляре уже установлены `qwen3:4b`, `qwen3.5:9b` и `bge-m3`. Повторная загрузка для продолжения работы не требуется. На другом компьютере установите Ollama с <https://ollama.com/download> и загрузите нужные модели.

```sh
ollama pull qwen3:4b
ollama pull bge-m3
```

`scripts/start.py` поднимает Ollama, если локальный сервис ещё не работает. Для поднятого им сервиса модели хранятся в `.runtime/models`, облачные модели отключены, включены Flash Attention и KV-кеш `q8_0`. Уже работающая Ollama используется с её текущими настройками. Отдельный запуск `server.py` поддерживает переменные `ISTOK_MODEL`, `ISTOK_OLLAMA_URL` и `ISTOK_EMBED_MODEL`.

Qwen выбирает предложения по идентификаторам. Программа извлекает точные исходные выдержки и их границы. Версия адаптера `sentence-selection-v4-exact-validation` дополнительно проверяет лексическое подтверждение метки `exact`. При противоречии выполняется одна повторная попытка. Если подтверждения снова нет, пара получает состояние «Нужна проверка редактора» с причиной и выдержками. Оно учитывается отдельно от ошибок запросов и исключает подготовку правки для этой пары.

Для правки кандидата сервер требует актуальную сохранённую положительную оценку. Предпросмотр показывает исходную выдержку, применение проверяет неизменность текста, идентификатор оценки и границы замены. Соседние авторские предложения сохраняются. Оформление цитаты для лексического совпадения доступно без модели.

## Поиск и фоновые задания

Поиск по словам использует BM25, поиск по смыслу — BGE-M3. На каждый фрагмент статьи выводится до пяти кандидатов. Сильнейший смысловой кандидат сохраняется в пятёрке при отсутствии общих слов. Это поведение проверялось на синтетических переводных примерах.

Представления источников кешируются локально по содержимому и контрольной сумме модели. Первая обработка библиотеки занимает больше времени, чем повторная.

Массовая проверка кандидатов показывает прогресс, четыре метки модели, случаи для ручной проверки и ошибки. Остановка дожидается текущего ответа модели, уже завершённые сравнения сохраняются по одному. После перезагрузки страницы возобновляется наблюдение за активными заданиями. При временной потере связи используются повторные подключения с задержками до 15 секунд. После перезапуска самого сервера задание может стать недоступным, сохранённые частичные ответы загружаются из базы.

## Диагностика качества и скорости

`data/examples.json` содержит 12 авторских синтетических пар. Четыре относятся к обучающей части, восемь — к диагностической. Исходные тексты этих частей разделены, однако диагностические пары уже использовались при настройке инструкций. Экспорт для обучения включает только вручную просмотренные примеры обучающей части. Дообучение модели ещё не проводилось.

`data/retrieval_examples.json` содержит 24 синтетических случая и 16 документов-источников. В тестовой части 16 случаев, включая 12 положительных и четыре независимых текста. Оцениваются попадание нужного источника и фрагмента в первые результаты, затем решение Qwen на найденной паре. Эти данные также использовались для отладки.

Доступные инструменты

```sh
python3 scripts/evaluate.py --model qwen3:4b --split test --output data/runs/example-pairs.json
python3 scripts/evaluate_retrieval.py --mode both --split test --output data/runs/retrieval.json
python3 scripts/benchmark_model.py --model qwen3.5:9b --output data/runs/example-9b-smoke.json
```

Последний инструмент измеряет время запросов, токены, наличие thinking, контекст и показатели резервирования памяти Ollama на восьми диагностических парах. Показатель Ollama `size_vram` на Mac с общей памятью не равен полному потреблению физической RAM компьютера.

Сквозная проверка поддерживает отдельный кеш и выбор модели

```sh
python3 scripts/evaluate_pipeline.py --model qwen3:4b --split test --top-k 5 --cache .runtime/compare-qwen4b-cache.json --output data/runs/qwen4b-current.json
python3 scripts/evaluate_pipeline.py --model qwen3.5:9b --split test --top-k 5 --cache .runtime/compare-qwen9b-cache.json --output data/runs/qwen9b-current.json
```

Для честного сравнения обе команды выполняются последовательно на одинаковом зафиксированном коде и наборе. Кеши разделены по прогону. Сохраняются digest модели, SHA256 кода, отпечаток данных, порядок и точные тексты кандидатов. Сравнение сохранённых результатов выполняется без обращения к моделям

```sh
python3 scripts/compare_pipeline_runs.py data/runs/qwen4b-current.json data/runs/qwen9b-current.json
```

Скрипт отклоняет несопоставимые данные, код или кандидатов. Он выводит полноту по размеченным случаям, ложные положительные находки, неопределённые ответы, ошибки, число запросов и медиану/p95 времени без кешированных ответов.

## Сохранённые диагностические результаты

- `pipeline-v2.json` содержит полный прогон старого снимка кода на 16 синтетических случаях. Qwen3 4B выполнила 84 запроса для 80 пар за 668,787 секунды. Нужный источник и ожидаемый участок найдены для 12 положительных случаев, на четырёх независимых статьях положительных находок нет. Одна дополнительная пара осталась неподтверждённой после повторной метки `exact`. Старый JSON хранит её как ошибку без отдельного `error_code`.
- `qwen35-9b-smoke.json` содержит восемь диагностических пар Qwen3.5 9B. Получено 8/8 ожидаемых меток, девять запросов за 122,309 секунды, thinking отключён, контекст 8192. Ollama сообщила максимальное резервирование модели 5 642 083 368 байт. На Mac уже использовался swap около 6,3 ГБ до и после прогона, выделить вклад одной модели из этих снимков нельзя.
- В `data/runs/` также сохранены первые пары `baseline.json`, `grounding-v2.json`, `grounding-v3.json`, поиск `retrieval-baseline.json`, `retrieval-v2.json` и исходный сквозной `pipeline-v1.json` с аудитом выдержек `pipeline-v1-audited.json`.

Прежний полный прогон 4B и новый короткий прогон 9B используют разные задания и снимки кода. По ним нельзя определить победителя 4B/9B. Свежий полный прогон 4B на текущем коде идёт. Сопоставимый полный прогон 9B ещё не завершён и запланирован после 4B. Результаты появятся в отдельных файлах. Независимая проверка на новых реальных статьях ещё предстоит.

## Проверки разработки

```sh
python3 -m unittest discover -s tests -v
node --check web/app.js
node --test tests/frontend.test.cjs
```

Последняя подтверждённая локальная проверка включает 130 Python-тестов и восемь Node-тестов. Интеграционные тесты используют временные базы и HTTP-серверы. Node-набор проверяет состояние и гонки через полный запуск JS с управляемыми DOM/API, включая сохранность черновиков и границы правок. Визуальную проверку выполняют отдельно.

Главная страница и основные действия проверены в разрешённом браузере на `127.0.0.1:8766` при ширинах 1440 и 375 пикселей. Проверены настоящий учебный отчёт, переключение источников, установка подборки без потери заполняемой формы и сохранность личного черновика. GitHub Actions настроен на Python 3.11/3.14, синтаксис JS и Node-регрессии.

## Следующие этапы

- Завершить сопоставимое сравнение 4B/9B, разобрать ошибки и стоимость времени на одинаковых парах.
- Собрать около 100 новых реальных случаев с ручной разметкой. Целые исходные статьи отложить до настройки порогов.
- Измерить попадание нужного источника, правильность выдержки, пропуски пересказов, ложные находки на статью и время редактора.
- После подтверждения качества расширить корпус, подключить веб-поиск и импорт DOCX/PDF с контролем извлечения текста.
- После накопления разметки проверить QLoRA и сравнить результат с исходной моделью на новых материалах.
- Подготовить сервер, аккаунты, бесплатные лимиты и оплату после измерения стоимости проверки.

Варианты аренды GPU и студенческого доступа исследованы. Платные ресурсы не заказаны, деньги не потрачены. Текущая версия работает локально на Mac.
