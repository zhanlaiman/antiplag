# Исток

Локальный прототип сверки редакторских текстов с собственной библиотекой и оценки Qwen для Mac.
Рабочее название проекта — «Исток».

## Запуск

Нужен Python 3.11 или новее. Python-зависимостей у приложения нет.
Откройте `Запустить Исток.command` или выполните в папке проекта

```sh
python3 scripts/start.py
```

Откройте <http://127.0.0.1:8766>. Процесс работает до закрытия терминала или Ctrl+C.
Источники, отчёты, ответы модели и ручные оценки хранятся в `data/istok.sqlite3`.
Отчёты содержат снимки источников, поэтому сохраняют доказательные фрагменты после удаления источника из библиотеки.

## Первая проверка

1. Нажмите «Учебный пример». Он добавит два авторских текста в библиотеку.
2. Запустите проверку. Подсветка ведёт к совпадающему отрывку источника.
3. Подтвердите или отклоните находку, при необходимости добавьте комментарий.
4. Выберите оформление цитаты или пересказ, просмотрите правку и примените её.
5. Запустите проверку ещё раз. Оформленная цитата по-прежнему будет совпадать с источником.
6. Добавьте собственные источники через вставку текста или TXT-файл.

Доля совпадений рассчитывается по объединению найденных символьных интервалов относительно всей длины текста. Пробелы внутри интервалов учитываются, пересечения считаются один раз. Результат относится к выбранной локальной библиотеке. Источник по ссылке автоматически не загружается.

Отчёты содержат неизменяемые снимки источников. Повторные отчёты ссылаются на сохранённые снимки, экономя место. Старые отчёты с вложенными текстами также читаются. Решения редактора сохраняются отдельно от исходных совпадений и их процента.

## Qwen

Ollama обслуживает модель через <http://127.0.0.1:11434>. Стартовый вариант — `qwen3:4b`.
Если Ollama ещё не установлена, установите её с <https://ollama.com/download>.
Запуск приложения поднимает локальную Ollama, если сервис ещё не работает.
Для загрузки модели при работающем сервисе

```sh
ollama pull qwen3:4b
```

При запуске через `scripts/start.py` модели сохраняются в `.runtime/models`, облачные модели отключены. Уже работающая Ollama используется с её текущими настройками и расположением моделей.
В интерфейсе можно выбрать другую установленную модель. Настройки для отдельного запуска сервера задаются переменными `ISTOK_MODEL` и `ISTOK_OLLAMA_URL`.

Qwen сравнивает найденную пару фрагментов, а также текст с конкретным выбранным источником. Проверяются точные выдержки, на которые ссылается модель. Пересказ со ссылкой предлагается для авторской проверки. Оформление цитаты работает без модели.

## Поиск пересказов в библиотеке

В отчёте доступен отдельный поиск кандидатов по словам и смыслу. Поиск по словам использует BM25, поиск по смыслу — локальную BGE-M3. Для её установки при работающей Ollama

```sh
ollama pull bge-m3
```

Обе модели уже загружены в текущем рабочем экземпляре проекта. Повторная загрузка при продолжении работы не нужна.

На каждый фрагмент статьи показывается до пяти кандидатов. Лучший результат поиска по смыслу сохраняется в пятёрке, даже если в нём отсутствуют общие слова с запросом. Это помогает находить переведённые фрагменты. Кандидаты сгруппированы по исходным участкам статьи, с сохранением точных позиций в обоих текстах.

Qwen может проверить кандидатов по одному или в фоновом задании. Прогресс и ошибки видны в интерфейсе. Задание можно отменить, уже завершённые сравнения сохраняются по одному. После обновления страницы интерфейс возобновляет наблюдение за активным заданием. При остановке самого сервера активное задание завершается, сохранённые ответы остаются в базе.

Для правки кандидата Qwen сначала выделяет конкретное предложение. Сервер сохраняет оценку и её границы. Предпросмотр показывает исходную выдержку и предлагаемую замену, применение проверяет неизменность текста и заменяет только выбранный участок. Соседний авторский текст сохраняется.

Представления источников кешируются локально по содержимому и контрольной сумме установленной модели. Первая обработка библиотеки занимает больше времени, чем повторная. Параметр `ISTOK_EMBED_MODEL` позволяет выбрать совместимую установленную модель поиска.

## Контрольные примеры и обучение

В `data/examples.json` находятся 12 небольших авторских примеров. Четыре отведены для обучения и ручной разметки, восемь — для диагностического прогона. Исходные тексты между этими частями не пересекаются. Восемь примеров уже использовались при отладке инструкций модели. Для независимой оценки качества нужен новый набор реальных размеченных материалов.

Сохранить первый результат модели

```sh
python3 scripts/evaluate.py --model qwen3:4b --split test --output data/runs/baseline.json
```

Сравнить другую установленную модель с сохранённым результатом

```sh
python3 scripts/evaluate.py --model istok-adapter --split test --output data/runs/adapter.json --baseline data/runs/baseline.json
```

В интерфейсе можно посмотреть ожидаемый ответ, ответ модели и сохранить ручную оценку. Экспорт для обучения включает только вручную просмотренные обучающие примеры. Контрольные примеры сохраняют исходную разметку для сопоставимых прогонов. Полное дообучение и импорт адаптеров ещё предстоит подключить.

Сравниваемые результаты содержат SHA256 исходных примеров, ошибки и время каждого ответа. Сравнение отклоняется, если исходные примеры или их ожидаемые ответы изменились. При оценке полноты `recall_all_cases` учитывает и неотвеченные положительные случаи.

Отдельная оценка поиска использует авторские синтетические примеры из `data/retrieval_examples.json`. Правильный источник ищется среди отвлекающих документов. Измеряются попадания источника и нужного фрагмента в первые 1 и 5 результатов. Обнаружение тематического кандидата проверяется следующим этапом сравнения пары.

```sh
python3 scripts/evaluate_retrieval.py --mode both --split test --output data/runs/retrieval.json
python3 scripts/evaluate_pipeline.py --split test --top-k 5 --output data/runs/pipeline.json
```

Последняя команда проверяет цепочку поиска и решений Qwen. Ответы кешируются с учётом содержимого обоих фрагментов, версии модели и кода её адаптера. Если прогон был прерван, повторный запуск использует сохранённые ответы. Оба набора относятся к отладочным. Реальную точность и время редактора нужно измерять на независимых статьях.

## Проверки разработки

```sh
python3 -m unittest discover -s tests -v
node --check web/app.js
```

Интеграционные тесты временно запускают HTTP-сервер на локальном адресе и используют отдельную временную базу.

## Дальнейшие этапы

- Подключить поисковый API и извлечение открытых веб-страниц с измерением полноты поиска.
- Проверить поиск по смыслу и переводных фрагментов на новых размеченных русско-английских статьях.
- Расширить контрольную выборку реальными статьями, цитатами и независимыми текстами на общую тему.
- Добавить импорт DOCX/PDF, распознавание сканов и контроль пропущенных страниц.
- Подключить QLoRA после накопления ручной разметки, сравнить модель с исходной на отложенных источниках.
- Подготовить размещение на сервере, аккаунты, лимиты бесплатных проверок и оплату после измерения стоимости одной проверки.

Первая версия предназначена для локального использования одним редактором. Поиск по интернету, платежи, автоматическое дообучение и обработка PDF/DOCX входят в следующие этапы.
