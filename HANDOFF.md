# Текущий этап «Истока»

Пользователь возобновил автономную работу 11 ноября 2026 года. Текущий сценарий — редактор сверяет статью со своей библиотекой, проверяет доказательные фрагменты и принимает решения по находкам.

## Что работает

- Локальный интерфейс на http://127.0.0.1:8766, запуск `python3 scripts/start.py`.
- Сохранение источников, отчётов, решений редактора, снимков исходных публикаций и результатов Qwen в `data/istok.sqlite3`.
- Точные и близкие лексические совпадения с исходными позициями, обработкой подмен похожих букв и невидимых символов.
- Отдельный поиск кандидатов BM25 + BGE-M3, до пяти на фрагмент статьи. Сильнейший смысловой кандидат сохраняется в пятёрке при отсутствии общих слов.
- Кеш представлений по содержимому и контрольной сумме модели.
- Фоновые задания с прогрессом и остановкой. Уже завершённые сравнения сохраняются по одному.
- Qwen выбирает существующие предложения по идентификаторам, программа извлекает точные выдержки и их границы. Выдержки не перепечатываются моделью.
- Правки кандидатов привязаны к сохранённой положительной оценке и заменяют только выделенную выдержку. Соседний авторский текст сохраняется.
- Черновик браузера и выбранная модель сохраняются локально. История предлагает явное восстановление текста отчёта.
- Снимки источников дедуплицированы в SQLite по SHA256. Старые отчёты читаются без миграции.

Обе локальные модели уже загружены в `.runtime/models` — `qwen3:4b` и `bge-m3`. Облачные модели отключены для сервиса, запущенного приложением. Повторная загрузка при продолжении не нужна.

Существовавшие ранее `output/` и `tmp/` относятся к другим материалам, их не включать в проектные изменения.

## Проверки и результаты

- Последний полный прогон — 89 тестов, все прошли. Проверены ядро, HTTP API, хранение, гонки, снимки источников, границы правок, очередь моделей, задания и диагностические инструменты. При новых изменениях повторить соответствующие проверки.
- `data/runs/baseline.json` — первый прогон Qwen, 5/8 ответов обработаны, 3 ошибки неточных выдержек.
- `data/runs/grounding-v2.json` — после выбора предложений, 8/8 ответов обработаны, 4/8 классов верны.
- `data/runs/grounding-v3.json` — после уточнения правил, 8/8 обработаны без ошибок, 7/8 подробных классов верны. Найдены 4 положительных случая, 4 отрицательных не отмечены как заимствования. Время 47,327 секунды. Этот прогон импортирован в историю приложения.
- `data/runs/retrieval-baseline.json` — на 12 положительных отладочных случаях BM25 нашёл источник в первой пятёрке 10 раз, начальный гибридный поиск — 11 раз.
- `data/runs/retrieval-v2.json` — после сохранения сильнейшего смыслового кандидата гибридный поиск нашёл источник и исходный фрагмент в первой пятёрке 12/12 раз. Попадание на первое место 10/12. Раздел содержит ещё 4 независимых текста, для которых кандидаты требуют отдельного разбора.
- `data/retrieval_examples.json` — 24 авторских синтетических отладочных случая и 16 документов-источников с непересекающимися группами между разделами. Это диагностический материал.

Восемь пар и синтетический набор поиска уже изучались при отладке. Эти результаты не являются независимой оценкой реальной точности.

## Работа, которая идёт сейчас

- Запущена сквозная оценка `python3 scripts/evaluate_pipeline.py --split test --top-k 5 --output data/runs/pipeline-v1.json`.
- Прогресс записывается в `.runtime/pipeline-live.log`, успешные ответы по одному — в `.runtime/pipeline-cache.json`.
- Кеш учитывает точные входные фрагменты, digest модели и SHA256 адаптера. Прерванный прогон можно продолжить той же командой.
- В первых случаях обнаружены ошибочные вердикты exact на выбранных предложениях без дословного совпадения. Точность самих выдержек обеспечивает проверяемость, правильность вывода требует отдельной оценки.
- После завершения исходного сквозного прогона планируется ограниченная проверка согласованности exact с лексическими свидетельствами и один повторный запрос при противоречии. Пока исходный прогон идёт, адаптер не менять, чтобы сохранить воспроизводимость.
- Добавить к сквозным метрикам проверку, относится ли выделенная моделью выдержка к ожидаемому месту источника. Правильный источник с неправильной выдержкой считать отдельным недостатком.
- Последние изменения фоновой массовой проверки и сохранения её ошибок повторно проверить по HTTP API и перезапустить рабочий сервер после завершения текущего прогона модели.

## Ограничение визуальной проверки

Предыдущая версия проверена в браузере на пути учебный пример → совпадения → точная цитата → применение.
Доступ браузера к отдельному тестовому адресу http://127.0.0.1:8767 был отклонён системой разрешений. Обход не выполнялся. Последние визуальные изменения не проверены в живом браузере. Продолжаются проверки HTTP API и логики интерфейса. Для визуальной проверки потребуется разрешённый доступ пользователя.
