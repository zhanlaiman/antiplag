# Текущий этап «Истока»

Состояние на 11 ноября 2026 года. Пользователь возобновил автономную работу. Цель — редакторский инструмент для сверки статьи со своей библиотекой, проверки доказательных фрагментов и сохранения решений по находкам.

- Для `17c23d3` успешно завершился GitHub Actions на Python 3.11 и 3.14, включая Python-тесты, синтаксис JS и Node-регрессии. Результат — https://github.com/zhanlaiman/antiplag/actions/runs/43008574321.
- `.runtime/`, локальная SQLite-база и `data/runs/` исключены из Git. Артефакты диагностических прогонов нужно сохранять отдельно от опубликованного кода.
- Существовавшие ранее `output/` и `tmp/` относятся к другим материалам. Их не включать в проектные изменения.
- Варианты аренды GPU и студенческого доступа исследованы и сохранены в `docs/GPU_OPTIONS.md`. Сервисы не заказаны, деньги не потрачены.

До внешнего запуска нужно проверить фактический Starter/$30 и установить custom Spend limit $0, Usage limit $30. Shared Model Endpoints оплачиваются отдельно и в план бесплатной проверки не входят.

## Рабочий запуск и данные

```sh
python3 scripts/start.py
```

Адрес — http://127.0.0.1:8766. Пустой hash открывает главную, `#check` — редактор. Для сохранённого браузерного черновика использовать тот же адрес и браузер. Личный текст об экономике на 4370 знаков сохранён и проверен на сохранность при работе с учебным примером.

В `.runtime/models` уже установлены `qwen3:4b`, `qwen3.5:9b` и `bge-m3`. Повторно модели не скачивать. Стартовый сервис Ollama использует локальный адрес, отключённые облачные модели, Flash Attention и KV-кеш `q8_0`. Запросы адаптера идут с `think=false`, контекстом 8192 и `temperature=0`.

`data/istok.sqlite3` содержит 32 источника — 14 реальных статей русской Википедии по экономике, 16 по биологии и два авторских демо. Экономическая подборка собрана из 15 запрошенных названий, один повтор исключён. Биологическая содержит все 16 запрошенных статей, 349 383 символа, без пропусков и дубликатов. Обе лежат в `data/source-packs/`, установка атомарна и идемпотентна.

Для источников сохранены лицензия CC BY-SA 4.0, атрибуция, история авторства, сообщённая API редакция, время получения и SHA256 текста. `revision_binding=reported_latest_revision` явно указывает границу происхождения. Извлечённый обычный текст не проверялся на точное тождество указанной редакции. Библиотека содержит полный полученный ответ без обрезания.

## Что работает

- Редактор, библиотека, история отчётов, экран диагностической оценки и новая главная страница с рабочим учебным сравнением.
- Точные и близкие лексические совпадения с исходными позициями, обработкой похожих букв и невидимых символов.
- Отдельный поиск BM25 + BGE-M3, до пяти кандидатов на фрагмент. Сильнейший смысловой кандидат сохраняется при отсутствии общих слов.
- Локальный кеш представлений по содержимому и digest модели.
- Фоновые поиск и массовая проверка Qwen, остановка после текущего шага, сохранение каждого завершённого ответа или ошибки.
- Наблюдение за заданиями восстанавливается после обновления страницы. Потеря связи вызывает повторное подключение с задержками 1/2/4/8/15 секунд. Исчезнувшее после перезапуска сервера задание завершается понятным сообщением и загрузкой сохранённых частичных результатов.
- Qwen выбирает существующие предложения по идентификаторам. Программа извлекает точные выдержки и их границы.
- Адаптер v4 `sentence-selection-v4-exact-validation` проверяет лексическое подтверждение `exact`, при противоречии делает одну повторную попытку. Повторно неподтверждённая метка даёт `unconfirmed_exact` с выдержками и состоянием «Нужна проверка редактора», без подготовки правки.
- Сервер принимает правку кандидата только по последней сохранённой положительной оценке, проверяя её актуальность до и после генерации. Ответ содержит `judgment_id` и абсолютные границы замены.
- Применение правки проверяет текущий текст, актуальную оценку и точное содержимое исходной выдержки. Соседние авторские предложения и переносы строк сохраняются.
- Кандидаты и результаты модели изолированы по идентификатору поиска и пары. Поколения запросов защищают от запоздалого восстановления старого положительного вердикта.
- Черновик текста, выбор модели и несохранённые комментарии сохраняются в браузере. Ответ сохранения сохраняет более новые правки комментария. История предлагает явное восстановление текста отчёта.
- TXT/MD читаются как строгий UTF-8, UTF-16LE/BE с BOM или предположительный Windows-1251 с уведомлением. Двоичные данные и превышение 200 000 Unicode-символов отклоняются до замены текста.
- Отчёты сохраняют дедуплицированные снимки источников в SQLite. Старые отчёты остаются читаемыми.

Процент отчёта относится к лексическим совпадениям в локальной библиотеке. Смысловые кандидаты, решения редактора и оформленные цитаты требуют отдельного просмотра. Произвольный веб-поиск, OCR, импорт PDF/DOCX, аккаунты и платежи ещё не подключены.

## Текущее честное сравнение 4B и 9B

Свежий полный прогон 4B завершён за 804,627 с — 80 пар, 84 запроса, 12/12 ожидаемых источников и участков, 0 положительных находок на четырёх независимых статьях. Одна пара `unconfirmed_exact`, сетевых/серверных ошибок нет. Медиана пары 8,791 с, p95 18,638 с. Сопоставимый полный 9B запущен последовательно после него и ещё идёт.

Root запустил новый полный прогон 4B на зафиксированном текущем коде

```sh
python3 scripts/evaluate_pipeline.py --model qwen3:4b --split test --top-k 5 --cache .runtime/compare-qwen4b-cache.json --output data/runs/qwen4b-current.json
```

Прогресс 4B — `.runtime/compare-qwen4b.log`, кеш — `.runtime/compare-qwen4b-cache.json`, полный результат сохранён. Во время сопоставимых прогонов не менять `llm.py`, `matching.py`, `retrieval.py` и `pipeline_evaluation.py`.

9B уже запущена с теми же данными, порядком кандидатов, параметрами и кодом, используя отдельный кеш. Прогресс — `.runtime/compare-qwen9b.log`. Уже запущенную модель не перезапускать. Текущая команда

```sh
python3 scripts/evaluate_pipeline.py --model qwen3.5:9b --split test --top-k 5 --cache .runtime/compare-qwen9b-cache.json --output data/runs/qwen9b-current.json
```

После получения обоих файлов

```sh
python3 scripts/compare_pipeline_runs.py data/runs/qwen4b-current.json data/runs/qwen9b-current.json
```

Сравнение требует одинаковых отпечатков набора, SHA256 адаптера/поиска/сопоставления, split, top-k и всех точных входных пар. Вывод включает найденные положительные случаи, ложные находки, ошибки, неопределённые пары и медиану/p95 времени без кешированных ответов. Digest каждой модели сохраняется отдельно.

Старый `pipeline-v2.json` использует SHA256 адаптера `a639ce76…` и сопоставления `84787e1c…`. Они отличаются от текущих файлов. Короткий 9B smoke также проверяет другое задание. Сравнивать их напрямую как равные условия 4B/9B нельзя.

`scripts/benchmark_model.py` измеряет восемь учебных пар и сообщает параметры модели, время запросов и состояние памяти. `scripts/compare_pipeline_runs.py` читает готовые JSON и не запускает модели. `scripts/evaluate_pipeline.py --audit-existing` позволяет повторно проверить расположение выдержек сохранённого прогона без запросов к модели.
